# M9 PX03 installed qualification

Run in the same M9 batch as the signed native installation and
[PX02 inventory qualification](m9-px02.md). Use the authorized disposable
single-node PVE 9.3.1 amd64 host and the merged signed candidate. Record the
candidate release digest, PVE package version, boot ID and fixture identities
in a private receipt. Keep the operator signing key and API credentials out
of receipts.

## Real guest operations

Use disposable QEMU 190 and LXC 191 with working graceful shutdown and no
pending changes or HA assignment. QEMU 190 needs `serial0: socket` and a guest
that responds to a carriage return with a login prompt. The gate waits up to
45 seconds for that prompt before submitting each graceful QEMU shutdown.
Keep guest 192 outside their scope. Use
stopped QEMU template 194 and unprivileged LXC template 195, with distinct free
destinations 196 and 197 in `rc2-managed`, `local-lvm` storage, and `vmbr0`
with the guest links down. Use current template generations and configuration
digests, exact target limits and the separate privilege-separated tokens
documented in the
[native operator guide](../../../docs/proxmox-native.md#confirm-native-guest-power-operations).
Set aside an authorized host checkpoint before the batch and reserve these
VMIDs and tokens for the gate until the batch ends.

Run from the matching test source on the installed PVE node as root. Use a
new receipt directory in `/root` for each batch.

```bash
umask 077
receipt=$(mktemp -d /root/m9-px03.XXXXXXXX)
python3 -I tests/integration/gates/m9_px03_native.py \
  --confirm-disposable-pve --evidence "$receipt/native.json"
```

The script checks each power leg against the matching successful native task
and current guest state. It explicitly confirms the start leg of each reboot
after observing a completed graceful shutdown and a stopped guest. It checks
the successful full clones against their archived tasks and observed target
properties. It then uses an occupied clone VMID to exercise PVE's collision
decision and verify that the original destination is preserved. A prepared
shutdown becomes stale after a separate authorized shutdown. Confirming the
stale job must leave the guest stopped and add no shutdown task.

The receipt records the current phase and job ID before dispatch and each
completed check. If the gate stops, keep its receipt and read that job's
status before resuming. A `running` receipt after interruption marks the last
checkpoint. Each whole run needs the original free VMIDs and matching
generations from the fixture checkpoint. Restore the checkpoint between
attempts. Preserve the receipt outside the checkpoint scope first.

## Confirm after revoking native permission

Run in a root Bash session on the same disposable node after the real guest
gate. Keep QEMU 190 running. Set `PVE_POWER_USER`, `PVE_POWER_TOKEN_ID` and
`PVE_POWER_ROLE` to the dedicated power principal's user, token ID and
existing custom role. Supply only the identifiers, never the token value.
Use the same private receipt directory. The checks expect one exact
non-propagating token grant at `/vms/190`.
[PVE ACL commands](https://github.com/proxmox/pve-access-control/blob/master/src/PVE/CLI/pveum.pm)

```bash
(
  set -euo pipefail
  umask 077
  : "${receipt:?}" "${PVE_POWER_USER:?}" "${PVE_POWER_TOKEN_ID:?}" "${PVE_POWER_ROLE:?}"
  node=$(hostname -s)
  principal="${PVE_POWER_USER}"'!'"${PVE_POWER_TOKEN_ID}"
  power() {
    timeout 65s /opt/opstend-pve/current/venv/bin/python -I -B \
      -m steward.cli.main pve-native power "$@"
  }
  acl_count() {
    timeout 10s pveum acl list --output-format json | python3 -I -c '
import json, sys
print(sum(row["path"] == "/vms/190" and row["type"] == "token"
          and row["ugid"] == sys.argv[1] and row["roleid"] == sys.argv[2]
          and row["propagate"] == 0 for row in json.load(sys.stdin)))
' "$principal" "$PVE_POWER_ROLE"
  }
  native_state() {
    timeout 10s pvesh --noproxy get "/nodes/$node/qemu/190/status/current" \
      --output-format json | python3 -I -c '
import json, sys
status = json.load(sys.stdin)
assert status["status"] == status["qmpstatus"] == "running"
print(status["status"], status["pid"])
'
    timeout 10s pvesh --noproxy get "/nodes/$node/tasks" --vmid 190 \
      --typefilter qmshutdown --source all --limit 20 --output-format json | python3 -I -c '
import hashlib, json, sys
upids = {row["upid"] for row in json.load(sys.stdin)}
print(hashlib.sha256("\n".join(sorted(upids)).encode()).hexdigest())
'
  }
  restore() {
    timeout 10s pveum acl modify /vms/190 --tokens "$principal" \
      --roles "$PVE_POWER_ROLE" --propagate 0
  }

  test "$(acl_count)" = 1
  power plan --vmid 190 --operation shutdown > "$receipt/acl-before.json"
  job=$(python3 -I -c 'import json,sys; print(json.load(sys.stdin)["job_id"])' \
    < "$receipt/acl-before.json")
  native_state > "$receipt/acl-native-before"
  trap 'restore' EXIT
  trap 'exit 130' INT
  trap 'exit 143' TERM
  timeout 10s pveum acl delete /vms/190 --tokens "$principal" --roles "$PVE_POWER_ROLE"
  test "$(acl_count)" = 0

  denied() {
    local rc=0
    local denied_result="$receipt/acl-denied-$1"
    power "$@" > "$denied_result.out" 2> "$denied_result.err" || rc=$?
    test "$rc" = 1 && test ! -s "$denied_result.out" && \
      printf '%s\n' 'error: PVE power evidence does not authorize the operation' | \
      cmp -s - "$denied_result.err"
  }
  # Verify the installed executor sees the revoked scope before confirming.
  denied plan --vmid 190 --operation shutdown
  denied execute --confirm "$job"
  power status --job-id "$job" > "$receipt/acl-status.json"
  cmp "$receipt/acl-before.json" "$receipt/acl-status.json"
  native_state > "$receipt/acl-native-after"
  cmp "$receipt/acl-native-before" "$receipt/acl-native-after"

  restore
  test "$(acl_count)" = 1
  power plan --vmid 190 --operation shutdown > "$receipt/acl-restored.json"
  trap - EXIT INT TERM
)
```

The two approvals remain unconfirmed and expire after five minutes. If the
session dies before the exit trap runs, reapply the exact non-propagating
grant with `pveum acl modify` as above and verify a fresh shutdown plan
succeeds. Leave that plan to expire too.

## Restart and read the same jobs

Set `PVE_POWER_JOB_ID` and `PVE_PROVISION_JOB_ID` to one succeeded job of each
kind from `native.json`. Use the same private receipt directory.

```bash
(
  set -euo pipefail
  umask 077
  : "${receipt:?}" "${PVE_POWER_JOB_ID:?}" "${PVE_PROVISION_JOB_ID:?}"
  agent=opstend-pve-agent.service
  native() {
    timeout 65s /opt/opstend-pve/current/venv/bin/python -I -B \
      -m steward.cli.main pve-native "$@"
  }
  jobs() {
    native power status --job-id "$PVE_POWER_JOB_ID" > "$receipt/power-$1.json"
    native provision status --job-id "$PVE_PROVISION_JOB_ID" > "$receipt/provision-$1.json"
  }
  fresh_after() {
    python3 -I -c '
import json, sys
from datetime import datetime
from pathlib import Path
before, after = (json.loads(Path(path).read_text()) for path in sys.argv[1:3])
sys.exit(not (before["status"] == after["status"] == sys.argv[3]
    and datetime.fromisoformat(after["observed_at"]) > datetime.fromisoformat(before["observed_at"])))
' "$receipt/$1-before-restart.json" "$receipt/$1-after-restart.json" "$2"
  }
  jobs before-restart
  native status > "$receipt/health-before-restart.json"
  native inventory > "$receipt/inventory-before-restart.json"
  systemctl show "$agent" --property=MainPID --value > "$receipt/agent-pid-before"
  sleep 1  # Health timestamps are published at one-second precision.
  timeout 60s systemctl restart "$agent" opstend-pve-ui.service
  systemctl show "$agent" --property=MainPID --value > "$receipt/agent-pid-after"
  old_pid=$(cat "$receipt/agent-pid-before")
  new_pid=$(cat "$receipt/agent-pid-after")
  test "$old_pid" -gt 0
  test "$new_pid" -gt 0
  test "$new_pid" -ne "$old_pid"
  jobs after-restart
  cmp "$receipt/power-before-restart.json" "$receipt/power-after-restart.json"
  cmp "$receipt/provision-before-restart.json" "$receipt/provision-after-restart.json"
  native status > "$receipt/health-after-restart.json"
  fresh_after health healthy
  deadline=$((SECONDS + 45))
  while true; do
    native inventory > "$receipt/inventory-after-restart.json"
    if fresh_after inventory observed; then
      break
    fi
    test "$SECONDS" -lt "$deadline"
    sleep 1
  done
)
```

If the signed lifecycle checks perform a compatible rollback, repeat the
two status reads after reactivating the candidate and compare with the
saved job results.

## Isolated response loss and replay

From the matching source with the development dependencies installed, run
the focused gate separately from the live PVE executor and retain its test
output with the batch receipt.

```sh
python -m pytest -q tests/test_pve_dispatch_integration.py
```

The test uses a verified local TLS listener on an ephemeral loopback port,
synthetic credentials and an isolated SQLite journal. The listener records a
typed write against an already-durable dispatch intent and drops the HTTP
reply. A reopened executor checks the uncertain job, refuses a mismatched
task, and reconciles the unique matching task and observed state. The
listener's request count must remain one across repeated confirmation. The
cases cover QEMU shutdown and full clones of both guest kinds, with simulated
PVE jobs and local clone readback. The installed PVE gate supplies real task,
guest, clone, ACL and collision evidence.
