# M9 PX02 installed qualification

Run this procedure in the M9 batch on the authorized disposable PVE 9.3.1
amd64 host, after installing the merged signed test candidate in standalone
mode. Record the release digest, installed `pve-manager` version and elapsed
times in a private receipt. The test signing key is independent of release
signing custody. Prior real API observations are recorded in
[the PX02 collector PR](https://github.com/grethel-labs/opstend/pull/12).

## Real PVE scope

1. Use the health credential with no effective ACLs and the separate
   privilege-separated inventory credential. Assign audited access to one
   disposable QEMU guest and one disposable LXC guest, a node, pool and
   datastore. Keep a third known guest outside the token's scope. Use
   direct, non-propagating grants on the exact paths listed in the
   [inventory API qualification](../../../docs/proxmox-native.md#inventory-api-qualification).
2. Capture the installed `pve-native inventory` JSON and both guests' detail
   JSON. Compare the inventory and details with the signed-in standalone
   HTTPS `/inventory` and `/guests/<vmid>` pages and their
   `Accept: application/json` responses. For a PVE-side reference use
   `pvesh get /version`, `pvesh get /cluster/resources`, and
   `pvesh get /nodes/<node>/<qemu|lxc>/<vmid>/config --current 1` as the test
   operator. Compare node and guest IDs and status, the visible pool
   association, datastore content, sharing and capacity, and the guest
   bridge and VLAN. Compare available hourly RRD samples and matching guest
   tasks using the corresponding endpoints in the qualification matrix.
   Record only the selected, sanitized fields. The out-of-scope guest
   must be absent from inventory and projections, and its detail must equal
   the response for an unused VMID in the same snapshot.
3. Temporarily remove the LXC's exact `VM.Audit` grant from the inventory
   token using the authorized PVE operator account. In the PVE permissions
   view confirm the grant is gone. Within 120 seconds, repeat the inventory
   and detail readback. The LXC, its network and related evidence must be
   hidden while the QEMU guest remains visible. Restore the saved ACL in
   the PVE permissions view and confirm the LXC and its evidence return
   within 120 seconds. Save the before, revoked and restored observations.

## Installed agent with isolated faults

Use a dedicated root Bash session on the same acceptance VM, from the
checked-out test source. The network namespace has only its own loopback
and the test API sees only synthetic tokens. The real
`pveproxy`, PVE CA and real scope are left in place. The standalone UI is
stopped during this portion. CLI continues to read the installed agent's
normal state directory.

```bash
set -e
umask 077
gate=/run/opstend-px02-gate
agent=opstend-pve-agent.service
ui=opstend-pve-ui.service
fixture=opstend-px02-api-fixture.service
dropin=/run/systemd/system/$agent.d/50-px02-gate.conf
pve_python=/opt/opstend-pve/current/venv/bin/python
inventory() { "$pve_python" -I -B -m steward.cli.main pve-native inventory "$@"; }
select_value() { printf '%s\n' "$2" > "$gate/next"; mv "$gate/next" "$gate/$1"; }

test ! -e "$dropin"
test ! -e /run/netns/opstend-px02-gate
test "$(systemctl show "$fixture" --property=LoadState --value || true)" = not-found
mkdir -m 0700 "$gate"
ip netns add opstend-px02-gate
ip -n opstend-px02-gate link set lo up
install -m 0600 tests/integration/gates/m9_px02_api_fixture.py "$gate/api.py"
for scope in health inventory; do
  printf 'px02@pve!%s=%s\n' "$scope" "$(cat /proc/sys/kernel/random/uuid)" > "$gate/$scope.token"
done
for chain in a b; do
  openssl req -x509 -newkey rsa:2048 -noenc -days 1 -subj "/CN=PX02 gate CA $chain" \
    -addext 'basicConstraints=critical,CA:TRUE' \
    -keyout "$gate/$chain-ca.key" -out "$gate/$chain-ca.pem"
  openssl req -new -newkey rsa:2048 -noenc -subj '/CN=px02-gate.invalid' \
    -keyout "$gate/$chain.key" -out "$gate/$chain.csr"
  printf '%s\n' 'subjectAltName=DNS:px02-gate.invalid' 'extendedKeyUsage=serverAuth' > "$gate/extensions"
  openssl x509 -req -days 1 -in "$gate/$chain.csr" -extfile "$gate/extensions" \
    -CA "$gate/$chain-ca.pem" -CAkey "$gate/$chain-ca.key" -CAcreateserial -out "$gate/$chain.pem"
  openssl x509 -in "$gate/$chain-ca.pem" -noout -sha256 -fingerprint > "$gate/$chain-fingerprint"
done
select_value mode ok
select_value chain a
install -m 0600 "$gate/a-ca.pem" "$gate/trusted-ca.pem"
systemd-run --unit="$fixture" --collect \
  --property=NetworkNamespacePath=/run/netns/opstend-px02-gate \
  --property="StandardOutput=append:$gate/requests.jsonl" \
  --property=StandardError=inherit \
  /usr/bin/python3 -I "$gate/api.py" "$gate"
timeout 10 bash -c 'until grep -Fq "$2" "$1"; do sleep .1; done' _ "$gate/requests.jsonl" '"listen": 8006'

systemctl stop "$ui" "$agent"
mkdir -p "$(dirname "$dropin")"
cat > "$dropin" <<EOF
[Service]
NetworkNamespacePath=/run/netns/opstend-px02-gate
ExecStart=
ExecStart=$pve_python -I -B -m steward.pve_native_runtime agent px02-gate.invalid
LoadCredential=
LoadCredential=pve-ca:$gate/trusted-ca.pem
LoadCredential=pve-token:$gate/health.token
LoadCredential=pve-inventory-token:$gate/inventory.token
EOF
systemctl daemon-reload
systemctl start "$agent"
inventory
```

If a check fails before the gate directory is created, stop and leave the
existing resources in place. Once the gate directory has been created,
use the cleanup below after any setup failure. Wait for
`observed` with the synthetic guest `9901` before changing the fixture.
After each change, poll `inventory` for up to 45 seconds and save the
first matching output, together with the fixture trace.

| Change | Required installed result |
|---|---|
| `select_value mode bad-version` | `unavailable`, `api_version/unsupported`, empty rows. Each inventory attempt stops at the version GET even though health receives the qualified version. |
| `select_value mode rate-limit` | `unavailable`, `guest_config/rate_limited`, empty rows. In `requests.jsonl`, the inventory attempt ends at that GET. The next inventory attempt starts at the version path on the normal 30-second cadence. |
| `select_value mode malformed` | `unavailable`, `cluster_resources/invalid`, empty rows. Each inventory attempt ends at the roster GET with duplicate response keys. |
| `select_value mode ok` | Fresh `observed` after the preceding faults. |
| `select_value chain b` | `unavailable`, `api_version/unavailable`, empty rows. During a full subsequent refresh there are no authenticated HTTP requests in the fixture log. |

For the confirm-and-rotate case, compare the fixture CA fingerprint with
the expected fingerprint from fixture generation and validate its endpoint
identity. Save the last `api_version/unavailable` result and the agent's
`MainPID` before replacing the source trust file. Poll for a newer
`observed_at` with the same evidence and the same PID to confirm the process
refuses the new chain at its next scheduled refresh. Restart the installed
agent and verify a new PID and fresh scoped read.

```bash
openssl x509 -in "$gate/b-ca.pem" -noout -sha256 -fingerprint > "$gate/confirmed-fingerprint"
cmp "$gate/b-fingerprint" "$gate/confirmed-fingerprint"
openssl verify -CAfile "$gate/b-ca.pem" -verify_hostname px02-gate.invalid "$gate/b.pem"
install -m 0600 "$gate/b-ca.pem" "$gate/next"
mv "$gate/next" "$gate/trusted-ca.pem"
# After checking the old process still refuses the chain, reload its credentials.
systemctl restart "$agent"
inventory
```

For the in-flight restart, wait for fresh `observed`. Set the hold mode
and let the next inventory roster request record its entry time. Kill the
old main process before its two-second read deadline. The fixture has
accepted the GET and is withholding its response. Require the signal to
finish within two seconds of the recorded request start, otherwise repeat
within the milestone's attempt budget.

```bash
old_pid=$(systemctl show "$agent" --property=MainPID --value)
rm -f "$gate/inflight"
select_value mode hold
timeout 45 bash -ec '
  until test -s "$1/inflight"; do sleep .02; done
  systemctl kill --kill-whom=main --signal=SIGKILL "$2"
  python3 -c "import sys, time; from pathlib import Path; assert time.time() - float(Path(sys.argv[1]).read_text()) < 2" "$1/inflight"
' _ "$gate" "$agent"
select_value mode ok
inventory
inventory --vmid 9901
```

The two immediate reads must show `unavailable` with empty rows and no
guest. Systemd restarts the agent after its configured delay. Within 45
seconds confirm a new, nonzero main PID distinct from `old_pid`, fresh
`observed` inventory and one synthetic guest. Save the interrupt time
and recovery time with the fixture trace.

## Restore the real endpoint

Save the sanitized fixture trace and results privately, then remove only
the gate resources. Restart both installed services with the original
credentials and verify the real inventory, API and guest observations
again. Use this cleanup after an interrupted test as well.

```bash
agent=opstend-pve-agent.service
ui=opstend-pve-ui.service
dropin=/run/systemd/system/$agent.d/50-px02-gate.conf
systemctl stop "$agent"
rm -f "$dropin"
rmdir "$(dirname "$dropin")" 2>/dev/null || true
systemctl daemon-reload
systemctl stop opstend-px02-api-fixture.service || true
ip netns delete opstend-px02-gate || true
rm -rf -- /run/opstend-px02-gate
systemctl start "$agent" "$ui"
/opt/opstend-pve/current/venv/bin/python -I -B -m steward.cli.main pve-native inventory
```

Record which checks used the real PVE API and which used the isolated
fixture. The fixture demonstrates the installed process and snapshot
behavior for controlled faults. PVE scope and inventory agreement require
the real endpoint portion.
